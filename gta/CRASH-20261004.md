- Crab creation returned entity 48642. The move clip was accepted and its native phase advanced through 0.27283, 0.55865 and 0.84040. Coordinates also changed. The owner nevertheless saw poor appearance and a glitching repeated animation. These counters do not pass visual acceptance. No crab attack/death was logged before clear.

- Rockstar's launcher recorded **Failed zlib call**, exit `0x15559348`, at 12:16:05. The dump contains **ERR_GEN_ZLIB_2** and an intentional `0x80000003` breakpoint in GTA5.exe. This is a game-reported streaming/decompression failure, not evidence that our melee routine or a GPU overload crashed.
- GTA exited and the guarded launcher did not restart it. Hari explicitly said to keep it closed and owns the next playtest.

Raw logs, crash context and dump are preserved privately in `~/Applications/EldenLosSantosPreview/Evidence/20261004-zlib-crash`; they are not public repository content.

## What the offline investigation establishes

`rpf_audit.py` independently reads the final nested archive and inflates its actual payloads using Python zlib. All seven installed resources have complete streams, no trailing/truncated data, and inflated sizes matching their page flags. Compressed resource payloads also match the pre-packaging files. This rules out those specific corrupt/truncated-archive hypotheses. It does **not** identify why GTA's live reader failed.

The material conversion unnecessarily retained seven unused Malenia textures and expanded generated maps into uncompressed RGBA8. Its YDR occupied 77,922,304 bytes (74.3 MiB) after inflation, with 32 MiB pages and a 25,560,435-byte stored resource requiring the extended-size header path. The crash context reports streaming virtual memory used 707 MB out of 767 MB available. These are concrete size/memory risks; neither the 16 MiB archive field boundary nor this snapshot proves the crash cause. Large resources are supported by the format.

The shader schema in pinned szio 1.4.0.dev1 explicitly supports the used skinned `normal_spec` vertex layout. Exported weights sum to 255 and all indices are within the palette. This avoids another speculative shader replacement. It still does not establish correct GTA skin/material rendering.

## Focused candidate

Only Malenia's embedded texture payload changes in the streaming candidate. Her mesh, bone data, materials' sampler references, render bounds, collision, source motions and gameplay ASI remain unchanged. The three YCDs, Wolf/Crab YDRs and YTYP are byte-identical. No roster expansion.

- Remove seven unreferenced embedded textures.
- Re-encode five generated maps as BC7 with full mip chains at their original dimensions, using pinned `ispc_texcomp==1.0.1` (`alpha_slow`, MIT). The first BC3 attempt failed the quality gate and was rejected.
- The largest normal-map 99th-percentile angular error is 1.90 degrees. Hair alpha threshold coverage changes by approximately 0.042 percentage points. Compression is lossy; it is not described as pixel-identical or visually accepted.
- New Malenia resource: **23,396,352 bytes (22.3 MiB) inflated; 11,701,271 bytes stored; largest page 8 MiB; no extended-size header**.
- New DLC SHA-256: `8393c6a54d39d1f6a6894de2217e8a6041fbeadb3e493172c3600abdbe66fd6f`.
- Independent audit passes for every resource. The 32 MiB per-resource limit is this preview's conservative review policy, not a universal GTA engine limit.

The live streaming failure remains **unverified as fixed** until the owner tries the smaller candidate. No texture encoding or unit test can replace that observation. If it still fails at the same stage, preserve the new dump and isolate the live resource-reader/loader path; do not keep changing combat or ask for an unchanged retry.

## Errors in the previous workflow

1. Same-tool export/read-back and synthetic tests were used as the main gates before basic native appearance had been established.
2. Source-resolution preservation was implemented with large RGBA intermediates and redundant embedded maps, without a reviewed final streaming budget.
3. Too many asset, animation and behavior changes accumulated between meaningful GTA observations. Accepted animation calls and phase advancement were insufficient diagnostics for the owner's visible problems.
4. A successful spawn was a useful milestone but did not establish a working, good-looking boss. This repair stays focused on one boss and explicitly separates streaming, appearance, animation, contacts and a complete fight.
